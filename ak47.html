03 Execution runtime

AK47 15m Desk

Production-grade execution layer for Kalshi BTC. Built for multi-day unattended runs with strict separation between signal generation and order execution, paper-first validation gates, and deep observability.

2026-08-16

AK47v7.62 release 0 + 24h acceptance cycle

Closed release item 0, repaired connection-epoch implementation, deployed, and proved both changes in production. Started a precisely bounded 24-hour acceptance cycle with defined safety gates and availability measurements.

  • Duty-cycle closing grace (commit 455694a): tape now stays open 5s after window close — proved with Coinbase frames continuing past boundary
  • Connection-epoch refactor (commit 2233f72): atomic socket reset, fresh OrderBook, preserved diagnostics; 10/10 epoch mutants killed
  • Production verification via /proc: commit, PID 431404, MAX_VOL_PCT=0.16, real reconnects exercised with clean ACK + snapshot
  • Subscribe-ACK watchdog: 56% failure rate observed; reduced exposure from full 15m window to bounded reconnect
  • Additional defects documented: backoff never resets, tape_members.py OOMs on large archives, stop() leaves state populated
  • Acceptance cycle started: 24h window, explicit safety rules, availability metrics tracked separately

Frozen conditions for the cycle: no reboot, no deployment, no config change. PID identity check at 24h boundary.

2026-08-15

Live verification + /proc endpoint

Added a lightweight HTTP /proc endpoint that returns current position, last fill, cycle health, and paper vs live parity status. Used by both Telegram bot and external monitoring.

  • Zero-auth read endpoint for internal dashboards
  • JSON + plain text modes
  • Integrated into existing agent runtime
2026-08-12

Paper-to-live promotion gate

Implemented hard gate: a run must complete N consecutive paper cycles within tolerance before live capital is enabled. Gate state is persisted and visible in status output.

  • Configurable tolerance and cycle count
  • Automatic promotion on success
  • Manual override path with audit log
2026-08-08

Telegram delivery + daily digest

Built a clean daily digest format sent at market close. Includes cycle count, fill summary, P&L attribution, and any alerts. Messages are generated from structured run data, not ad-hoc prints.

  • Consistent message schema
  • Threaded daily summary
  • Separate high-priority alert channel
2026-08-03

Multi-day run stability

Refactored the main loop to survive network blips, API rate limits, and partial fills without losing state. Added automatic recovery with exponential backoff and state checkpointing.

  • State machine with persistent checkpoints
  • Idempotent order submission
  • Automatic resume after restart
